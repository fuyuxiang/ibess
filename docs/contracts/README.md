# 公共协议与兼容性

唯一实现位于可安装包 `packages/ibess-common/src/ibess_contracts`。`schemas/v2` 随 Python 包进入镜像；测试使用同一份 JSON Schema 和语义校验，不再依赖仓库外的 `contract_validator`。

| 对象 | 校验内容 |
| --- | --- |
| observation | 发生时间、媒体区间、业务绑定、阶段、模型信息、质量状态、证据引用 |
| risk-clue | 三态结论、风险等级、参与轨迹、观察及证据引用；未知业务绑定不能认定违规 |
| evidence-ref | 来源、媒体运行、起止、哈希和可用状态 |
| phase-config | 阶段快照、启用场景、规则版本及例外 |
| control-ack | 已应用、缺素材、失败回执及对应时间和错误信息 |
| asset-manifest | 授权素材声明、相对路径、摘要和时长 |
| event-message | 告警标识、来源、场次、时间、风险及状态 |

公共规则参数由 `rule_parameters.py` 定义，API 和事件消费者通过兼容模块导入同一个对象。协议结构校验与场景派发中的上下文校验分别负责不同约束：多机位融合可以引用不同来源的证据，但必须保持同一项目、评标室和场次；单观察派发还会核对其快照和发生时间。

当前版本为 `2.0.0`。新视觉观察和告警会携带版本号，消费者在滚动升级期间继续接受历史无版本 Redis 消息，拒绝未知版本。序列化保留原始抓拍时间、媒体运行和关键帧标识；不得以推理完成时间覆盖证据时间。

数据库采用六阶段名称；历史观察协议仍兼容既有九阶段别名。新增字段须保持旧读端可用；不兼容变更应新增协议版本及双读迁移测试。规则和提示词版本分别记录，不能用协议版本代替模型版本。

`fixtures/` 全部是合成示例，不含现场视频或身份信息。`stage_assets/manifest.example.json` 仅演示清单结构，其中零值摘要不能用于真实素材登记。新增契约须同时提交正常、错误版本、错误时间、跨作用域等测试，并通过 `python tools/check.py unit`。
